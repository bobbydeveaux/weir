# Proof: deployment

Which test proves each requirement. `make spec` checks that every requirement is listed here and that every test named exists.

| Requirement | Proven by |
| --- | --- |
| A database must be named, as one address or in parts | `internal/config/config_test.go:TestFromEnvRequiresDatabase`, `internal/config/config_test.go:TestTheDatabaseCanBeGivenInParts`, `cmd/weir/main_test.go:TestMigrateNeedsADatabase` (the address that is built is asserted; connecting with it is not) |
| The address to listen on comes from the environment | `internal/config/config_test.go:TestFromEnvDefaults`, `internal/config/config_test.go:TestTheDatabaseCanBeGivenInParts` |
| An unknown runner is refused | `internal/config/config_test.go:TestFromEnvRunner`, `internal/config/config_test.go:TestFromEnvRejectsUnknownRunner` (`WEIR_RUNNER` is asserted; `serve` refusing `api` and a bad `WEIR_AGENT_RUNNER` are not, and are in `serve` in `cmd/weir/main.go`) |
| Lists and pairs are read from single settings | `cmd/weir/main_test.go:TestListsAndPairsAreReadFromSettings` |
| Migrating creates the schema and the default workspace | `engine/store/migrate_test.go:TestMigrateCreatesTheDefaultWorkspace` (migrating is asserted; a server refusing a database that was never migrated is not, and is in `New` in `engine/engine.go`) |
| Migrations started together take turns | `engine/store/migrate_test.go:TestMigrationsStartedTogetherTakeTurns` (the test says it would also pass without the lock on a quiet machine; the lock is in `engine/store/migrate.go`) |
| There is an image for the server and one for agents | Not tested: `.github/workflows/images.yml` builds both images on a pull request that touches `deploy/`, and nothing starts a container from either |
| Docker Compose starts Postgres, and Weir when asked | Not tested: `compose.yaml` is used by hand and by `make up`; CI starts its own Postgres and never runs the `weir` profile |
| The Helm chart installs the server on Kubernetes | Not tested: CI runs `helm lint` and `helm template` on the chart (`.github/workflows/ci.yml`), and no test installs it. `deploy/helm/chart_test.go:TestTheChartIsUnchangedWithoutSecretFiles` asserts only that `existingSecret` becomes the server's and the migration's environment; the scenarios here are not asserted |
| A server can answer the API without doing the work | `cmd/weir/main_test.go:TestWhetherAServerDoesTheWork` (how the setting is read is asserted; a server that starts no worker, and two servers sharing a database, are not) |
| The certificate authorities for the database can be named | `internal/config/config_test.go:TestTheCertificateAuthoritiesForTheDatabaseCanBeNamed`, `internal/config/config_test.go:TestTheCertificateAuthoritiesAreRefusedBesideOneAddress` (the address Weir builds is asserted; checking the database's certificate against the file is done by the Postgres driver and is not tested here) |
| The database can be signed in to with an AWS IAM token | `internal/database/database_test.go:TestEachNewConnectionSignsInWithATokenOfItsOwn`, `internal/database/database_test.go:TestAnOpenConnectionOutlivesItsToken`, `internal/database/database_test.go:TestAMigrationSignsInWithAToken`, `internal/database/database_test.go:TestAConnectionIsNotOpenedWhenATokenCannotBeMade`, `internal/database/database_test.go:TestAnRDSTokenNamesItsHostUserAndRegion`, `internal/database/database_test.go:TestATokenTheDatabaseRefusesIsNotInTheError` (a Postgres role that accepts only a password stands in for RDS, with the password made for each connection; a sign-in to a real RDS database, credentials from EKS Pod Identity or a role for a service account, and `cmd/weir` choosing the AWS token when the setting is `aws` are not tested) |
| IAM sign-in is refused when a setting contradicts it | `internal/config/config_test.go:TestIAMSignInRefusesASettingThatContradictsIt`, `internal/config/config_test.go:TestIAMSignInBuildsAnAddressWithNoPassword` |
| The Helm chart supports IAM sign-in to the database | `deploy/helm/chart_test.go:TestTheChartMountsTheDatabasesCertificateAuthorities`, `deploy/helm/chart_test.go:TestTheChartRefusesIAMSignInWithAMigrationJob` (the chart is rendered, not installed; both tests are skipped on a machine without `helm`, and CI has it) |
| The Helm chart mounts secret files from a volume | `deploy/helm/chart_test.go:TestTheChartMountsSecretFilesFromACSIVolume`, `deploy/helm/chart_test.go:TestTheChartMountsSecretFilesFromASecretBesideTheDatabasesCertificateAuthorities`, `deploy/helm/chart_test.go:TestTheChartIsUnchangedWithoutSecretFiles` (the chart is rendered, not installed; a CSI driver mounting the files, and the server reading `WEIR_ADMIN_KEY_FILE`, are not tested here; the tests are skipped on a machine without `helm`, and CI has it) |
| The Helm chart refuses secret files that cannot work | `deploy/helm/chart_test.go:TestTheChartRefusesSecretFilesThatCannotWork` (rendered with `helm template`; skipped on a machine without `helm`, and CI has it) |
